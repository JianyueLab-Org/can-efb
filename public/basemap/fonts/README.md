# 地图字体（glyphs）

MapLibre 画任何文字都要一个 `glyphs` 字体源 —— 它把字形切成 PBF，按 Unicode 区段
请求。没有它，带 `text-field` 的图层**一个字都不会渲染，而且不报错**（style 校验
器也不会提示，它只检查语法）。

这里放的是 **Noto Sans Regular** 的两个区段：

| 文件 | 覆盖 | 大小 |
| --- | --- | --- |
| `0-255.pbf` | 基本拉丁字母、数字、常用标点 | 76 KB |
| `256-511.pbf` | 扩展拉丁 | 127 KB |

**只要这两段，是因为图上的文字就这些**：五字码（XUTGU）、导航台标注
（`D 113.1 SJD`）、空域垂直范围（`GND-41100`）、航路代号（V14、A461）——
全是拉丁字母和数字。

**中文不走这里。** 地名和空域名里的汉字由 `localIdeographFontFamily` 处理：
MapLibre 用本机字体在客户端画 CJK，不请求 glyphs。全套 CJK 字形切片是几十 MB，
为几个地名背这个体积不值得。

## 为什么自备而不是指向公共字体服务

这张底图**没有任何外部请求** —— 陆地是仓库里的 GeoJSON，没有瓦片服务。指一个公共
glyphs 端点就会把这个性质破坏掉：多一个第三方依赖、多一条会挂的链路，而且它挂的时
候表现是"文字消失"，很难联想到字体服务。

204 KB 换掉一个外部依赖，值得。
